# /epic-flow — アウターループ

`.claude/contexts/dev.md` を先に読むこと。仕組みの詳細は `docs/04_ループエンジニアリング.md` 2〜3 章。

エピック: **$ARGUMENTS**

エピックの切り方は `docs/00_計画と決定事項.md` 6 章のフェーズに合わせる: `p1-skeleton` / `p2-domain` / `p3-front` / `p4-async` / `p5-finish` / `p6-reverb`。

## 手順

### 1. 計画（planner）
1. `planner` サブエージェントを起動し、エピックを `docs/01_技術仕様_next.md` 10 章の担当分担に沿ってタスクに分解させる
2. planner が `.claude/state/STATE.md` にタスク表を書く（ID / タスク / 担当 / 所有ファイル / 完了条件 / 状態=未着手 / 依存）
3. planner が質問を返したら、**分解を進めずに人へ質問する**

### 2. 人の承認（チェックポイント 1）
- タスク表を要約して人に見せ、承認を待つ。**承認前に実装を始めない。リードが代行しない**（第2弾ではここを省いてしまった）
- 承認後、`STATE.md` のエピック表に `ブランチ: epic/<エピック名>` を書き、`git switch -c epic/<エピック名>`

### 3. タスクの実行（issue-flow の繰り返し）
- 依存関係の順に、タスクごとに `/issue-flow <タスクID>` を実行する
- 並列にしてよいのは、docs/01 の 10.2（api の A / B / C）と 10.3（web の WA / WB / WC）だけ。**同時に実装 3 体・レビュー 4 体まで**。レビューが 4 体を超えるときは担当ごとに順番に回す
- 基盤（10.1）と非同期（10.4）は直列
- 並列中、リード（あなた）は **全担当が終わるまで終了しない**（終了すると Stop フックが途中状態の全テストを回して赤になる）
- タスクが `requires-human` になったら、他の独立タスクは続けつつ、人に報告する

### 4. 統合
- 全タスクが `完了` になったら `/verify full` を実行する
- 赤ならその時点で Stop フックの検証ループが働く。緑になるまで直す（`build-error-resolver`）

### 5. 人の最終確認（チェックポイント 2）
- `STATE.md` のエピック行を `完了（人の確認待ち）` にし、次を人に提示する
  - 実装したタスク一覧、`make verify` の結果、`loop-log.md` の差し戻し回数
  - `myteam-acceptance` の手動確認手順のうち、このエピックで確認できるようになった項目
  - 人の作業が必要なこと（フェーズ移行、`.env` の反映、マイグレーションのロック）
- 人が OK したら `main` にマージし、エピック行を `完了`。**次のフェーズへは人が `.claude/.phase` を書き換えてから進む**

## ハードストップ
- planner の質問が 2 往復しても解消しない → 止めて人に判断を仰ぐ
- 同一タスクが issue-flow で 2 回 `requires-human` になる → エピック全体を一時停止
