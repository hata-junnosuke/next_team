# /plan — 計画

`.claude/contexts/research.md` を先に読むこと（読み取りのみ、結論は表で）。

対象: **$ARGUMENTS**

1. `planner` サブエージェントを起動し、対象を分解させる。渡すもの: 対象の F-xx、`docs/01` の 10 章、`STATE.md` の既存タスク
2. planner の出力（タスク表・曖昧点・見積り）を受け取り、曖昧点が残っていれば **実装に進まず人に質問する**
3. タスク表を `STATE.md` に反映済みか確認する
4. 人に「このタスク表で進めてよいか」を示して止まる。承認後は `/issue-flow <タスクID>` または `/epic-flow` へ

## 良い完了条件の 3 要素（ループエンジニアリングの「明確なゴール定義」）
- 測定可能: api はテスト名、web は tsc / ESLint の緑と手動チェック項目の番号
- 証明方法: `make api-test FILTER=X` が緑／`make web-typecheck` が緑
- 守る制約: 所有ファイル以外を触らない、契約（docs/01）を変えない、パッケージを足さない
