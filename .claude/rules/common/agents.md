# エージェントの使い分け（常時適用）

| 場面 | 委譲先 | 備考 |
|---|---|---|
| 機能を実装する前 | `planner`（`/plan`） | 完了条件はテスト名（web は型と ESLint の緑 ＋ 人が画面で確かめる項目） |
| 契約（テーブル・サービス・API の形・画面と API の対応）を変える | リード | `docs/01_技術仕様_next.md` の変更案を作り、人の承認を得てから書く |
| `api/` のコードを書く | `implementer-api` | 1 担当 1 体。所有ファイルだけ |
| `web/` のコードを書く | `implementer-web` | 同上。`api/` のコードは読まない（契約は docs/01 の API 契約） |
| テストの網羅を確認 | `tester` | 実装は直さない。`api/tests/` だけ書く |
| レビュー | `spec-reviewer` ∥ `code-reviewer` ∥ `security-reviewer` を並列 | 読み取り専用 |
| マイグレーション確定前・集計実装後・非同期のテーブル追加後 | `database-reviewer` | ロック可否を判定 |
| テスト・Pint・型・ESLint が赤 | `build-error-resolver` | 最小差分 |

- **レビュアーは書かない、実装者はレビューしない**（作る役と確認する役の分離）
- 所有ファイル以外を触る必要が出たら、リードに報告して止まる。契約に関わるならリードが人に相談する
- サブエージェントの「完了しました」は判定材料にしない。テスト結果とレビュー表で判定する
- **同時に動かすのは実装 3 体・レビュー 4 体まで**（多く起動するとセッションの利用上限に達して途中で止まる）
- **同じファイルを触る担当は同時に 1 体**。`tester` と `implementer`（指摘の反映）は直列にする
- モデルは **既定が `opus`**（`planner` を含む全エージェント）。`fable` は必要なときだけ使う: 人が指示したときか、リードが分解・契約の判断が難しいと見たとき（Agent の呼び出しで `model: fable` を指定する）。上限に達したら各エージェント定義のコメントに従って `sonnet` に切り替える
- リード（メインセッション。worktree で起動する Claude を含む）も既定は `opus`。`fable` が要るときは人が `/model` で切り替える（エージェント定義ではリードのモデルは変えられない）。上限に達したら人が `/model` で `sonnet` に切り替える
- 担当が動いている間、リードの Stop フックは検査を飛ばす（`.claude/.running/` の印）。全体の緑は、最後の担当が終わった後のリードの終了で判定される
