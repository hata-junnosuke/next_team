# 学習ポイント — 第3弾で何をどこで学ぶか

作成日: 2026-10-01 / ステータス: **実装前の学習計画**。「このアプリのどこ」は docs/01 の契約にある予定の場所です。実装後に `doc-updater` が実際のファイルパスとハマりどころで埋めます。

第1弾で「ルート → コントローラ → FormRequest → サービス → モデル → ビュー」、第2弾で「Fortify・Policy・モデルイベント・after-commit イベント・ロック・SQL 集計」を学んだ前提で、**第3弾で初めて出てくるもの** だけを並べます。Laravel の機能には Rails の対応概念を添えています。

読む順番は、フェーズの順（P1 → P4）がそのまま学ぶ順です。

---

## 0. 全体像: リクエストが 2 段になる

第2弾まではブラウザ → Laravel の 1 段でした。第3弾は 2 段です。

```
ブラウザ ──→ Next サーバ（:3002）──→ Laravel API（:8002）──→ SQLite
              HTML を作る                JSON を返す
                                          └→ Redis ──→ ワーカー ──→ Mailpit（P4 から）
```

| 役割 | 第2弾 | 第3弾 |
|---|---|---|
| HTML を作る | Laravel（Blade） | Next（Server Component） |
| 業務ルール | Laravel（サービス） | Laravel（サービス）。**変わらない** |
| 入力エラーの表示 | Laravel がセッションに入れて Blade が出す | Laravel が 422 の JSON で返し、Next が出す |
| ログイン状態 | セッション Cookie | セッション Cookie。**変わらない**。ただし Cookie を Next サーバが転送する |

Rails で言うと、「Rails のビューをやめて API モード（`rails new --api`）にし、前に Next を置いた」構成です。

### 問い（手を動かして確かめる）

- **Cookie は通るのに、なぜ CORS の設定が要るのか**: `localhost:3002` の画面から `localhost:8002` へのログインで、`config/cors.php` の `supports_credentials` を `false` にすると何が起きるか。ブラウザの開発者ツールのネットワークタブで見る（Cookie のスコープはポートを見ないが、オリジンはポートを見る）
- **CSRF Cookie を先に取るのは何のためか**: `/sanctum/csrf-cookie` を叩かずに `/login` へ POST すると何が返るか（419）
- **Fortify と Sanctum の責務の違い**: `make api-routes` で、どのルートがどちらのパッケージから来ているかを見る。Fortify は「ログインという処理」、Sanctum は「API にログイン状態を運ぶ手段」
- **サーバ側 fetch に Cookie は自動で付かない**: `lib/api.ts` から `Cookie` ヘッダの転送を外すと、ログインしているのに 401 になる。なぜか
- **`Origin` ヘッダを外すとどうなるか**: Sanctum は「どこから来たリクエストか」でセッション認証を有効にするかを決めている（`SANCTUM_STATEFUL_DOMAINS`）
- **zod の `parse` が落ちるのはどんなときか**: Resource のフィールド名を 1 つ変えて画面を開く。エラーメッセージに何が出るか

- **`lockForUpdate()` が効かない SQLite で、定員はなぜ守られるのか**: `php artisan tinker` を 2 つ開き、片方で `DB::beginTransaction()` した後、もう片方で `DB::beginTransaction()` するとどうなるか。`transaction_mode` を `DEFERRED` に戻すと挙動はどう変わるか

Rails と評価が分かれる点: **Observer** は Rails では「どこで何が起きるか追いにくい」として 4.0 で本体から外されましたが、Laravel では公式機能です。今回はキャッシュの破棄という「どの経路でも必ず起きてほしい副作用」に限って使います。業務ルールを Observer に入れると Rails が外した理由と同じ問題が起きます。

### 問い

- **ワーカーを止めたまま承認すると何が起きるか**: 画面は返るか。Redis には何が入っているか（`redis-cli -h localhost LLEN queues:mails` など。キー名は Horizon の接頭辞に注意）。ワーカーを起動するとどうなるか
- **イベントから `ShouldDispatchAfterCommit` を外すとどうなるか**: 定員エラーで巻き戻った承認の通知が出るか、テストで確かめる
- **ジョブにモデルを渡す（`SerializesModels`）のと ID を渡すのは何が違うか**: 承認の直後にキャンセルして、ワーカーを起動する。どちらの書き方なら通知が出ないか
- **`$tries` と `backoff()` を書かないとどうなるか**: Mailpit を止めて承認する。何回試して、どれくらいの間隔で、最後はどこに記録されるか
- **`failed()` はいつ呼ばれるか**: 1 回失敗するたびか、全部失敗した後か
- **「送信 → 記録」と「記録 → 送信」のどちらを選ぶか**: それぞれ、どの瞬間に落ちると何が起きるか（docs/03 の 4.3）
- **`withoutOverlapping`・`ShouldBeUnique`・UNIQUE 制約は、それぞれ何を防いでいるか**: キャッシュを全部消したら、どれが残るか
- **署名付きURL の `signature` は何から作られているか**: `APP_KEY` を変えると、発行済みの URL はどうなるか
- **キャッシュの破棄をトランザクションの途中でやると何が起きるか**: 破棄 → 別リクエストが再計算（まだコミット前の値）→ コミット、の順を紙に書く
- **Horizon と Telescope の違いを一言で言うと**: 「キューの今」と「1 回の処理の中身」

## ハマりどころ（実装しながら追記）

`.claude/state/learnings.md` の信頼度 0.7 以上をここへ昇格させます。最初から分かっているもの:

| 発見 | どこで | 対処 |
|---|---|---|
| Next 16 は `middleware.ts` が `proxy.ts`、`cookies()` と `params` が Promise | web 全体 | 書く前に同梱ドキュメントを読む |
| ポート 3000 は別プロジェクトが使用中 | 起動 | web は 3002、api は 8002 |
| 同じブラウザで別の弾を開くと `XSRF-TOKEN` Cookie が上書きし合う | ログイン | 手動確認は別プロファイルで |
| `php artisan test --compact` と Pint は非 TTY で JSON を出す | フック | `jq` で整形（`verify-loop.sh`） |
| Pint が日本語テスト名の英字部分を snake_case に直す | テスト名 | テスト名は日本語だけで書く |
| SQLite の `LIKE` には既定の ESCAPE 文字がない | F-04 の氏名検索 | `LIKE ? ESCAPE '!'` |
| date の列に `whereBetween` を使うと月末日が漏れる | F-17 | 半開区間 |
| `Model::create()` の戻り値は DB の既定値を持たない | `status` | モデルの `$attributes` で揃える |
| Faker の `ja_JP` の人名がテストの文字列検査と衝突 | テスト | `phpunit.xml` で `en_US` に固定 |
| bash で変数名の直後に日本語が続くと変数名の一部になる | フック | `${VAR}` と書く |
