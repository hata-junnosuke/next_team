## 1. 第3弾で変えること（第2弾との差分）

| 観点 | 第2弾 `ecc_team` | 第3弾 `next_team` |
|---|---|---|
| 画面 | Blade + Tailwind CDN | **Next.js 16（App Router）+ TypeScript + Tailwind 4（手書き）** |
| Laravel の役割 | 画面 + 業務ロジック | **JSON API 専用**（Blade は認証画面も持たない） |
| 認証 | Fortify（セッション・Blade 画面） | **Sanctum SPA 認証**（Cookie + CSRF）＋ **Fortify ヘッドレス** |
| 非同期 | なし（すべて同期） | **Mail / Job / Queue（Redis + Horizon）/ スケジューラ / バッチ** |
| インフラ | SQLite のみ、Docker なし | **Docker Compose**（Redis・Mailpit）。DB は SQLite 継続 |
| ドメイン実装 | — | **ゼロから書き直す**（第2弾は README と ER だけ読む） |
| ハーネス | 1 スタック | **2 スタック**（api / web）。実装担当を 2 種類に分ける |

**変えないこと**: 動線 10 ステップ、業務ルールはサービス層に置く考え方、状態遷移は `transitionTo()` 経由、ECC ハーネス＋ループエンジニアリングの運用、DB（SQLite）。

**要件として変えたこと**（`00_要件定義.md` に反映済み）:

- 4.7「通知・非同期処理」を新設: F-20〜F-23 は Must、F-24 と F-25 は Could
- F-02: 第3弾からメール必須（通知の宛先になるため）
- 1 章: 20 時間の上限を第3弾には適用しない
- 7 章・8 章: 非同期を実装する弾だけに適用する非機能要件と完了条件

### 2.1 仮計画の時点（2026-09-18）

## 4. 追加で学ぶ機能（決定17・18）

過去 2 弾で触れていない機能を、要件を増やさずに実装の中身として入れます。

| 機能 | どこに乗せるか | 学習テーマ | Rails で言うと |
|---|---|---|---|
| Job / Queue | F-20〜F-23 のすべて | 投入、再試行、失敗の記録、キューの分離 | Active Job + Sidekiq |
| Horizon | キューワーカーと監視 | スーパーバイザ、キューごとの制御、失敗の再実行 | Sidekiq の Web UI |
| Mailable / Notification | F-20〜F-22 は Mailable、F-23 は Notification | 2 つの違い、チャネル | Action Mailer / Noticed gem |
| スケジューラ | F-22 | 定時実行、`withoutOverlapping` | whenever / sidekiq-cron |
| Artisan コマンド | F-22 を `app:send-reminders {--date=}` に | 引数・オプション、手動実行とテスト | rake タスク |
| ジョブバッチ | F-23 | `Bus::batch()`、進捗、`then` / `catch` | Sidekiq Pro の Batches |
| Storage ＋ 署名付きURL | F-23 の成果物 | ディスクの抽象、`signed` ミドルウェア | Active Storage + `signed_id` |
