# ワーカーアプリ（Flutter）学習計画

作成日: 2026-10-28 / ステータス: **計画（未着手）**

既存の企業側管理画面（`api/` と `web/`）に、**ワーカーがスマホで使う Flutter アプリ（`mobile/`）** を足します。ワーカーはログインして募集を探し、応募できます。応募や確定は管理画面と同じデータを通じて連携します。

読者の前提: Flutter はまだアプリを作ったことがなく、本を 1 冊読んだ段階です。Laravel・Next.js（React）・Rails の経験はあります。そこでこの計画では、**新しい概念が出てくるたびに React / Next.js / Rails のどれに当たるかを添えます**。

## 1. 学び方の型（全ステップ共通）

各ステップを **「1 機能 = 1 コミット」の小さな増分** で進めます。コードは Claude が書きます。あなたは動かして、変更点の案内を読み、わからない所を聞きます。1 つ機能を足すごとに区切るので、`git log` がそのまま教科書の目次になります。

| 手順 | 誰が | 何をするか |
|---|---|---|
| ① 宣言 | Claude | 次に足す機能を 1 つだけ示す。画面で何が変わるかと、新しく出てくる概念を先に言う（公式 URL つき） |
| ② 実装・コミット | Claude | コメント多めで実装し、`flutter analyze` が 0 件であることを確かめて 1 コミットにする |
| ③ 動かす | あなた | シミュレータで `r`（ホットリロード）か `R`（ホットリスタート）を押し、「確認」を通す |
| ④ 変更点の案内 | Claude | そのコミットの差分を、ファイルと行ごとに「何が新しいか・なぜこう書くか・React / Rails で言うと何か」で案内する。差分は Orca（`orca file diff`）か Cursor の差分表示で、横に並べて見る |
| ⑤ 質問・説明 | あなた | わからない所を聞く。案内の最後に出る「説明できるか」に 2〜3 行で答え、`docs/06_ワーカーアプリ学習メモ.md` に溜める。済んだら「次」と言う |

- 1 機能は 15〜30 分で回る大きさにする。**「次」と言われるまで、次の機能に進まない**
- 書くことにはこだわらない。試したくなったら自分で書き換えてもよい（そのときは Claude に差分を見せて相談する）
- **1 ステップは 1〜2 日で終わる大きさ**に切ってあります。最初の 1 週間で「スマホに募集一覧が出る」ところまで行きます

### 道具の分け方（Orca と Cursor）

| 道具 | 使う場面 |
|---|---|
| **Orca** | ターミナル（`flutter run`、`r` でホットリロード・`R` でホットリスタート、`flutter analyze`）、Claude Code、ブラウザ（DevTools・図解・管理画面） |
| **Cursor**（エディタとしてだけ使う） | Claude が書いたコードと差分を読む（定義へのジャンプ・型の表示・ホバーの説明が効く）。試しに書き換えてもよい。Cursor から起動（F5）すれば、保存するだけでホットリロードされる |

Cursor の AI について守ること: **`next_team/` のコードを Cursor の AI（チャット・Agent）に書かせない。** フック（`.env` の保護、Stop フックの検査）と CLAUDE.md のルールは Claude Code にしか効かないため。書かせるのは Claude Code だけにする。

ほかに気をつけること:
- Cursor はコードを索引にしてサーバに送る。`.env` は `api/.gitignore` と `web/.gitignore` で除外されている。気になるなら Privacy Mode を有効にする
- Flutter の公式文書は VS Code 向けに書かれている。Cursor は VS Code を元にしたエディタなので、画面やメニューを読み替えればそのまま使える（https://docs.flutter.dev/tools/vs-code ）
- Cursor で開くのは、その issue の worktree のフォルダ（例: `~/orca/workspaces/next_team/issue-31`）。`mobile/` だけを開くと Dart の解析がいちばん正確になる

## 2. コメントの書き方（`mobile/` のルール）

Claude が `mobile/` を書くときは次のルールに従います。のちに `mobile/CLAUDE.md` にも書き写します。

1. **ファイルの先頭**に「このファイルの役割」と「Next.js / React で言うと何か」を書く
2. **Dart の文法が初めて出てくる箇所**に一言添える（`?` `!` `late` `required` `final` / `const` / `=>` / `async*` / `sealed` / パターンマッチ など）。2 回目以降は書かない
3. **Widget ごとに**、何を表示するかと、なぜ `Stateless` / `Stateful` / `Consumer` を選んだのかを書く
4. **Riverpod の Provider ごとに**、何を持つか、いつ作り直されるか（`ref.watch` / `ref.invalidate`）を書く
5. **「なぜこう書くか」を優先**する。「何をしているか」はコードを見ればわかるので短く済ませる
6. 公式ドキュメントの該当ページの URL を、ファイルの先頭か初出の箇所に付ける

例:

```dart
// 募集一覧の画面。
// Next.js で言うと app/jobs/page.tsx に当たる。
// ただし Server Component ではなく、データの取得は Riverpod の Provider に任せる。
//
// ConsumerWidget = Provider を読める StatelessWidget。
// 自分では状態を持たず、Provider の値が変わると build() が呼ばれ直す
// （React で言うと、props / context が変わったときの再レンダー）。
class JobListScreen extends ConsumerWidget {
  // const コンストラクタ: 中身が変わらない Widget を使い回せるので、再描画が軽くなる。
  const JobListScreen({super.key});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    // ref.watch = 値を読み、変化を購読する（React の useContext + 自動の再レンダー）。
    final jobs = ref.watch(jobListProvider);

    // AsyncValue は「読み込み中 / エラー / データ」の 3 状態を持つ。
    // when で 3 つ全部を書かないとコンパイルが通らないので、ローディングの表示を書き忘れない。
    return jobs.when(
      loading: () => const Center(child: CircularProgressIndicator()),
      error: (e, _) => ErrorView(error: e),
      data: (list) => JobListView(jobs: list),
    );
  }
}
```

### A.3 5 章に足す動線（4.8 を実装する弾）

> 1. 管理者がワーカー「山田」を登録する → 山田のメール宛に招待が届く
> 2. 山田がワーカーアプリの初回登録で、メール・招待コード・パスワードを入れる → ログインした状態になる。同じ招待コードはもう使えない。ログアウトしても、企業コード・メール・パスワードでログインし直せる
> 3. 山田が「ピッキング」の募集（勤務日は今日以降）を探して応募する → 管理画面の応募一覧に「応募中」で出る。もう一度応募しようとするとエラー
> 4. 管理者が山田を確定する → 山田の応募一覧に「確定」で出る。確定通知メールも届く（F-20）
> 5. 管理者が定員まで確定する → 山田以外のワーカーのアプリで残り枠が 0 になり、応募できない
> 6. 管理者が募集を中止する → 山田の応募一覧に「キャンセル（企業都合）」で出る（F-07）
